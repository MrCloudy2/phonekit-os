# M10b verification: tethering (phone's Wi-Fi → PC over USB)

Status: 🟨 2026-11-17. Phone side verified; the PC side (actually browsing through the phone) is left to the
owner, because it changes the PC's default route.

```bash
scripts/ppctl.py wifi tether on
```
With Wi-Fi connected, paneld enables IP forwarding and NATs the USB network out of `wlan0`
(`iptables -t nat -A POSTROUTING -s 10.42.0.0/24 -o wlan0 -j MASQUERADE`, static iptables 1.8.11 legacy from
`scripts/build-wifi-tools.sh`; the kernel already has IP_NF_NAT + MASQUERADE). The USB network's DHCP then offers
the phone (10.42.0.2) as router and the Wi-Fi network's DNS, lease 10 min. The PC switches over at its next DHCP
renewal or a replug. `wifi tether off` removes the rule, turns forwarding off and goes back to the
"no router" offer (the PC keeps its own internet).

| Check | Result |
|---|---|
| on: `ip_forward` = 1, MASQUERADE rule, DHCP offers router + DNS | ✅ |
| off: forwarding 0, rule gone, plain offer again | ✅ |
| The test PC's default route untouched (it kept its old lease) | ✅ |
| PC browses through the phone | ⬜ owner test (NetworkManager: replug in PHONEBOX mode with tethering on) |
| Throughput | ⬜ |
| Cellular uplink | ✗ not on this phone (Exynos Shannon modem needs Android's RIL); Qualcomm phones could |
