Status: ✅ confirmed 2026-11-15. Automated: `scripts/test-touch.py` (all checks pass).

| Confirm item | Result |
|---|---|
| All touch points tracked | ✅ 10 simultaneous contacts (driver max: 10 slots), per-finger strokes and colours |
| Coordinates correct in all 4 rotations | ✅ logical→panel mapping verified at 0/90/180/270 (exact to the pixel) |
| Touch-to-photon latency < 50 ms | ✅ (software part measured): event timestamp → frame flushed **avg 28 ms**, min 5, max 33 ms. Physical scan-out adds ≤ 16.7 ms (60 Hz), so ≈ 45 ms worst case. A high-speed-camera measurement is still open |

## How it's tested without hands
- `ppctl touch tap|ltap|swipe|multi …` creates a **uinput** multitouch device shaped like the panel. Injected
  contacts take the full kernel → evdev → paneld path. The injector runs in a forked child, so the main loop
  keeps processing and timing the events.
- `ppctl tstats` reports touches, frames, last panel/logical point and latency min/avg/max.
- `ppctl screenshot out.png` dumps the visible frame. DECON fbdev has no `read()`, so paneld sends it from
  its own mmap (`fbdump`).

## Fixes along the way
- **Latency 254 ms → 28 ms.** paneld flushed (FBIOPAN, waits for vsync ~16.7 ms) once per touch report
  (~8 ms apart), so a queue built up. Now it drains all pending events, draws, and flushes once.
- **ppctl transfers > 2 MiB hung.** The client buffer was immutable `bytes` (quadratic copying), the reader fell
  behind, and the host tty dropped data. Now a `bytearray`: 4 MiB in 0.2 s (~20 MB/s), md5 verified.
- Touch device clock set to CLOCK_BOOTTIME (EVIOCSCLOCKID) so event timestamps compare with paneld's clock.
- Input devices are rescanned every 2 s (fast until the touchscreen exists), for hotplug and the injector.
