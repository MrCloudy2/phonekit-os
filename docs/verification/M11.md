# M11 verification: PHONEBOX over Wi-Fi (secure pairing) (Samsung Galaxy XCover Pro)

Status: ✅ 2026-11-17 (Linux PC). The phone pairs over USB and then talks to the phonebox agent over HTTPS with the
agent's certificate pinned and its token, exactly like the phonebox app's Wi-Fi route. Verified on a real home
network with the cable pulled and plugged back.

## How it works
1. In phonebox's settings turn on **Wi-Fi & Tailscale** (the agent then also listens on HTTPS port 8766) and restart it.
2. Plug the phone in once (PHONEBOX mode). Over the USB tunnel PhoneKit reads `/api/pair`: the PC's addresses,
   the port, the bearer token and the SHA-256 fingerprint of the agent's self-signed ECDSA P-256 certificate.
   They go into the settings store (the token is masked in `store` dumps). It refreshes on every USB connection.
3. Without the cable (or when the USB tunnel is gone) PhoneKit connects to the PC's addresses in turn with TLS
   (BearSSL 0.6, `scripts/build-bearssl.sh`), trusting **only** the certificate with the pinned fingerprint, and
   sends `Authorization: Bearer <token>`. When the cable comes back, USB wins again.
4. A PHONEBOX phone on Wi-Fi only (cable out) doesn't count as "PC gone" for standby.

| Check | Result |
|---|---|
| Pairing over USB | ✅ addresses, port, fingerprint, token stored; token masked |
| Stream over TLS with the pinned certificate + token | ✅ agent logged `live stream opened (phone, Wi-Fi)`; pages and live data as over USB |
| Wrong fingerprint is refused | ✅ `TLS error 62` (BR_ERR_X509_NOT_TRUSTED), no data; the right one reconnects |
| Same network, cable out | ✅ the agent logged `live stream opened (phone, Wi-Fi)`; **1.5 s** from unplug to the Wi-Fi stream (after the fix below) |
| Cable back | ✅ USB wins: **2.6 s** from replug to the USB stream; the Wi-Fi stream is closed, never both at once |
| After a reboot with the cable in | ✅ Wi-Fi may come up first; it hands over to USB 4.7 s after the USB tunnel |

Fixes from this run: the first unplug took 37 s, because the phone tried the PC's addresses in the agent's order
(LAN, a Docker bridge, the USB link itself) with a 15 s connect timeout each. Now it skips the USB link address,
tries addresses on its own Wi-Fi subnet first and gives up on one after 4 s. And "USB wins" was only checked
between stream events; on a slow link one event (album art) took minutes, so the main loop now cuts the Wi-Fi
stream as soon as the USB tunnel is up (also with the screen off).

Link notes: the test spot had a weak 2.4 GHz signal (-77 dBm, 13 Mbit/s RX rate) and a Wi-Fi extender (duplicate
ping replies); the stream kept working but album art loads slowly at ~0.4 MB/s. The PC firewall needed
`ufw allow from <phone> to any port 8766 proto tcp`.

Firewall note for users: the PC must accept TCP 8766 from the phone's network (the phonebox app needs the same).
