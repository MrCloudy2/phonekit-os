# M11 verification: PHONEBOX over Wi-Fi (secure pairing) (Samsung Galaxy XCover Pro)

Status: 🟨 2026-11-17. The phone pairs over USB and then talks to the phonebox agent over HTTPS with the agent's
certificate pinned and its token, exactly like the phonebox app's Wi-Fi route. Verified end to end over a local
tunnel; a real two-device Wi-Fi run (phone and PC on the same network) is pending.

## How it works
1. In phonebox's settings turn on **Wi-Fi & Tailscale** (the agent then also listens on HTTPS port 8766) and restart it.
2. Plug the phone in once (PHONEBOX mode). Over the USB tunnel PhoneKit reads `/api/pair`: the PC's addresses,
   the port, the bearer token and the SHA-256 fingerprint of the agent's self-signed ECDSA P-256 certificate.
   They go into the settings store (the token is masked in `store` dumps). It refreshes on every USB connection.
3. Without the cable (or when the USB tunnel is gone) PhoneKit connects to the PC's addresses in turn with TLS
   (BearSSL 0.6, `scripts/build-bearssl.sh`), trusting **only** the certificate with the pinned fingerprint, and
   sends `Authorization: Bearer <token>`. When the cable comes back, USB wins again.
4. A PHONEBOX phone on Wi-Fi only (cable out) doesn't count as "PC gone" for standby.

| Check | Result |
|---|---|
| Pairing over USB | ✅ addresses, port, fingerprint, token stored; token masked |
| Stream over TLS with the pinned certificate + token | ✅ agent logged `live stream opened (phone, Wi-Fi)`; pages and live data as over USB |
| Wrong fingerprint is refused | ✅ `TLS error 62` (BR_ERR_X509_NOT_TRUSTED), no data; the right one reconnects |
| Same network, cable out | ⬜ the test PC's firewall drops inbound 8766 on its USB link, and the phone's Wi-Fi is a different network (a hotspot), so the run above went through an `adb reverse tcp:8766` tunnel to 127.0.0.1 — same TLS, pinning and token code, different transport |

Firewall note for users: the PC must accept TCP 8766 from the phone's network (the phonebox app needs the same).
