# M4 verification: power manager and battery care (Samsung Galaxy XCover Pro)

Status: 🟨 functional checks ✅ (2026-11-15, `scripts/test-power.py` all pass); long-duration items pending.

| Confirm item | Result |
|---|---|
| Battery stays inside the charge window for 72 h | ⬜ mechanism verified (below), 72 h run pending (combine with the M1 24 h soak) |
| Battery temp limit respected; overheat path tested | ✅ temp_limit → charging off; temp_crit → screen forced off + CPUs capped; recovery after cooling |
| Blank → wake in < 300 ms | ✅ **263 ms** (host wake: unblank + backlight). Power key uses the same path |
| Idle power, screen blanked, < 100 mW | ❌ **133 mW** (blanked + CPUs capped). Taking CPUs 1–7 offline saves only ~11 mW. Below 100 mW needs system suspend: see "Next" |
| Clean power loss | n/a so far: everything lives in the initramfs (RAM). Applies once settings persist (M8/M14) |
| Battery-less boot | ⬜ needs a physical test (XCover Pro has a removable battery) |

## Behaviour (paneld/power.c)
- **Screen**: active → dim (backlight `dim`, default 12) after `dim_after_s` (60) → off (FBIOBLANK powerdown,
  CPUs capped to min freq) after `off_after_s` (300). Only real input counts as activity.
  - Touch wakes from dim. In off, the TDDI touch controller sleeps with the panel (`nvt_ts_close` on blank), so it
    **can't wake from touch**. Keys and the host (`ppctl power wake`) wake it.
  - **Power key**: short press toggles off/on; **held 3 s → reboot** (replaces the M0 "any press reboots").
- **Charge limiter**: `charging_enabled=0` above `charge_hi` (60 %), `1` at/below `charge_lo` (40 %). USB keeps
  powering the phone and the battery current reads **0 µA** while held. Re-asserted every 30 s (the battery
  driver may re-enable on cable events).
- **Thermal**: `temp_limit` (45.0 °C) stops charging; `temp_crit` (55.0 °C) forces the screen off and caps CPUs
  until the battery is 3 °C below. Samsung's battery driver keeps its own swelling/temperature charging control underneath.
- Settings: `ppctl power set <key> <value>`, status `ppctl power`.

## Next (deep standby, later milestone)
Suspend-to-RAM when off (phones idle ~10–20 mW suspended). Open design questions: the USB control channel
drops while suspended; wake sources (power key yes; host/USB activity and timers need RTC alarms or a
wake-capable gadget). Worth it for battery-powered installs; on USB power 133 mW ≈ 1.2 kWh/year.

## 2026-11-16: wake from off fixed; auto-dim/off default to never
- **Black picture after wake** (backlight on, touch working): Samsung's `decon_pan_display()` only updates the
  DMA source; its `decon_set_par()` call is `#if 0`'d. After a powerdown, which resets the window registers, the
  window stays disabled. Every pan "succeeds", but the panel shows the black background. It only became visible in
  SCREEN mode, because a static desktop sends no new frames. Fix: after unblank, paneld forces
  `FBIOPUT_VSCREENINFO` (fbdev's `fb_set_par` = `decon_set_par`), then re-presents for 1 s; no pans while blanked.
  User-verified in SCREEN mode.
- **Defaults**: auto-dim and auto-off are now **never** (user request: a mounted panel shouldn't sleep on its own);
  both stay in Settings. The power key and host DPMS still turn the screen off.
