## Confirm 2: flash ↔ restore round trip ✅ (2026-11-15)

Result:
- Backed up the phone's recovery partition first: identical to the release `recovery.img` (sha256 `16b39d24…ff75`).
- 1st flash got undone: `persist.vendor.recovery_update=true` restored the LineageOS recovery on the next boot.
  Set it to false, flashed again; our image (sha256 `171351b7…8b54`) survived a full LineageOS boot.
- `adb reboot recovery` → phonepanel: test pattern correct (colour order, red border on all 4 edges),
  touch paints under the finger, Power → reboots into LineageOS. Log: [M0-boot1.log](M0-boot1.log).
- Restored the backup with heimdall: partition hash matches the original again, and `adb reboot recovery` brings
  LineageOS recovery back up (its adb enumerates).

Facts learned (now in `device.yaml`):
- `paneld` (PID 1) starts **2.45 s** after kernel start; framebuffer ready at 2.48 s.
  (Bootloader time before the kernel isn't measured yet; M1 measures power-on → pixels.)
- fbdev 1080×2340, ARGB8888 (r16 g8 b0 a24), stride 4320, **virtual height 4680 = double buffer available**.
- Touch `sec_touchscreen` (event5), power key on `gpio_keys` (event4).
- The kernel services the watchdog itself (`s3c2410wdt_shutdown: watchdog is still alive` at reboot), so userspace needn't touch it.
- "unable to open an initial console": no console device on this kernel; harmless, logging goes through `/dev/kmsg`.
- `sec_bat_get_battery_info: Fail to set psy` every ~10 s: the battery driver misses the Android-side helper. Look at it in M4.

### Procedure used

phonepanel goes on the **recovery** partition, so the boot partition (LineageOS) is never touched.
The worst case is losing recovery until you reflash it in download mode.

Restore image (keep it): the LineageOS `recovery.img` from the 2026-11-02 release
(`xcover_pro-archive-2026-11-02/flash/release/recovery.img`; `SHA256SUMS` sits next to it).

### Before you start
- In LineageOS: Settings → System → Developer options → **Update recovery** must be **off**. Otherwise LineageOS overwrites our image on boot.
  On this build it was **on** by default: `persist.vendor.recovery_update=true` makes the `vendor_flash_recovery` service
  restore `/vendor/etc/recovery.img` on every boot. Check with `adb shell getprop persist.vendor.recovery_update`
  (not `persist.sys.recovery_update`); turn it off with the toggle or `adb root && adb shell setprop persist.vendor.recovery_update false`.
  After flashing, confirm the partition survived a LineageOS boot:
  `adb exec-out 'dd if=/dev/block/by-name/recovery bs=1M' | sha256sum` against `out/<device>/phonepanel.img.sha256`.
- Also turn on **Rooted debugging** (the build is userdebug) so you can read the logs afterwards.

### Steps
1. Power off. Hold **Vol Up + Vol Down** and plug in USB → download mode → Vol Up to continue.
2. `make flash device=samsung-xcoverpro` (= `heimdall flash --RECOVERY out/samsung-xcoverpro/phonepanel.img --no-reboot`).
3. Leave download mode and boot recovery: hold **Vol Down + Power** until the screen goes off, then
   immediately switch to **Vol Up + Power**. (Easier alternative: let it boot LineageOS, then `adb reboot recovery`.)
   If the combo lands in LineageOS, keep USB connected to a PC and retry (newer Samsung bootloaders want a cable for recovery).
4. Expected on screen: colour bars on the top half, a grey ramp, a dark area at the bottom, and a red 1 px border. Touching anywhere paints cyan squares.
5. Press **Power** → the phone reboots into LineageOS. (Without input it reboots by itself after 300 s.)
6. In LineageOS, collect the log:
   ```
   adb root
   adb shell 'cat /sys/fs/pstore/console-ramoops* 2>/dev/null || cat /proc/last_kmsg' > docs/verification/M0-boot1.log
   grep paneld docs/verification/M0-boot1.log
   ```
7. Restore: download mode again, then `heimdall flash --RECOVERY <LineageOS recovery.img> --no-reboot`, then boot recovery → the LineageOS recovery UI appears.

### If something goes wrong
| Symptom | Meaning | Action |
|---|---|---|
| Black screen, power key reboots to LOS | paneld runs, fb path wrong | Capture the log (step 6); the `fb:` lines tell us why |
| Black screen, nothing responds, reboots after ~5 min | paneld runs, no fb, no input | Same as above |
| Black screen, nothing ever happens | kernel didn't reach `/init`, or panicked | Hold Vol Down + Power ~10 s → forced reboot to LOS; capture the log |
| "Upload mode" screen | kernel panic | Vol Down + Power ~10 s; capture the log |
| Bootloader refuses the image (AVB/"not official") | footer issue | Flash the restore image; report the exact message |
