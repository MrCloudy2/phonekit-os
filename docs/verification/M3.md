# M3 verification: low-power display pipeline (Samsung Galaxy XCover Pro)

Status: ✅ confirmed 2026-11-15. Automated: `scripts/test-display.py` (all pass).

| Confirm item | Result |
|---|---|
| Static screen: lowest CPU idle state, paneld CPU < 1 % | ✅ paneld **< 0.01 %** of one core with the 1 Hz clock; CPUs ~100 % in cluster sleep (cpuidle state1) |
| 1 Hz clock redraws only its rectangle | ✅ 1 frame/s, damage = 576×64 px (**1 % of the screen**) via `ppctl fstats` |
| Idle → no page flips | ✅ 0 frames in 10 s with nothing changing |
| Power measured | ✅ fuel-gauge method, table below |

## Power (fuel gauge in slate mode = true system draw, 2026-11-15)
`scripts/power-measure.sh` (runs on the phone) suspends USB input (`batt_slate_mode=1`), samples
`batt_current_ua_now` and `voltage_now` every 0.5 s, then restores charging. No USB power meter needed.

| State | Draw |
|---|---|
| Static screen, backlight 306 (max) | 2289 mW (618 mA) |
| Static screen, backlight 128 | 1158 mW (306 mA); 916 mW in an earlier run |
| Static screen, backlight 10 | 525 mW |
| Static screen, backlight 0 (link still streaming) | 492 mW |
| Display blanked (FBIOBLANK powerdown) | **168 mW** |
| Blanked + both clusters capped at min freq | **130 mW** |

Conclusions for M4:
- **The backlight dominates** at normal brightness (128 → +666 mW over backlight 0), so auto-dim/brightness policy is the #1 lever.
- **Display on costs ~325 mW** even when black (DSI video stream + DECON + panel).
- Blank-on-idle (→ 168 mW) and capping CPU frequency while blanked (→ 130 mW) are the next levers.

## Variable refresh rate: what this hardware allows
- The panel (NT36672A) runs **DSI video mode** (`dsim: video mode`): DECON streams the full frame at 60 Hz
  whenever the display is on, and the panel has no frame memory. So partial updates and skipping frames
  save CPU/memory work, not panel/link power. paneld's damage tracking is still right (and needed for
  command-mode panels on other devices).
- Refresh comes from the device-tree timing in the DTBO (`nt36672a`: refresh 60, v-porch 8/10/2,
  DSI HS clock 1117 MHz). The DSIM VFP register is **8 bits**, so stretching the porch only reaches ~54 Hz.
- A real low-refresh idle mode (e.g. 30 Hz) would mean lowering the DSI PLL (`timing,pmsk`/`dsi-hs-clk`).
  It's a safe experiment (a panel that doesn't lock leaves the kernel and USB alive), but the expected gain is
  only part of the ~325 mW link cost. **Deferred**, behind blank-on-idle and backlight policy, which save far more.

## Implementation
- `fb_fill` grows a damage rectangle; `fb_present()` pans only if something was drawn, and records frames,
  pixels and the last damage rect (`ppctl fstats`).
- Main loop sleeps until the next wall-clock second or input. Touch events are batched to one present per vsync (M2).
- 5×7 bitmap font (`paneld/font.c`) for status text until the widget engine (M8).
- `ppctl blank on|off`, `ppctl clock on|off`.
