# M5 verification: USB gadget framework and mode switching (Samsung Galaxy XCover Pro)

Status: ✅ confirmed 2026-11-15. Automated: `scripts/test-usb.py`, `scripts/test-keys.py` (all pass).

| Confirm item | Result |
|---|---|
| A ↔ B at runtime re-enumerates without rebooting the phone | ✅ control channel back in ~1 s, ACM ports stay at interfaces 0/2/4 |
| Unplug/replug 50× recovers automatically | ✅ 50/50 via UDC `soft_connect` (in mode A, so the host's NetworkManager stays quiet), worst 0.9 s |
| Console ACM present in both modes | ✅ log/control/shell at interfaces 0/2/4 in A and B |
| Mode persisted | ✅ settings store survives reboots and deploys |

## Modes
- **A, display**: HID multitouch digitizer (10 contacts, 0–32767). The host sees a "phonepanel" touchscreen and
  phone touches arrive at the right position (centre tap → 16398/16390). GUD display joins in M6.
- **B, smart**: USB network, phone 10.42.0.2/24 with DHCP (udhcpd) offering 10.42.0.1, no router/DNS, so the host
  keeps its own default route. Ping < 1 ms.
  - **RNDIS, not NCM**: Samsung's NCM on this kernel receives but never transmits (TX 0 packets). RNDIS works with
    Linux (`rndis_host`) and Windows out of the box. `store set usb_net ncm` selects NCM (e.g. for macOS hosts).
- Switching: `ppctl usb mode A|B`, XCover key long press, or a 2 s long-press in the top-left corner.
  "Waiting for host" = the status line shows the UDC state (`not attached` / `configured`).

## Settings store
Two CRC32 slots in [partition_end − 2 MiB, end − 1 MiB) of phonepanel's own (recovery) partition;
`scripts/phone.sh flash` skips the region, so deploys keep settings. `ppctl store [set k v]`.

## Side buttons (configurable)
`keys.c`: short/long press (800 ms) per key → action, bound via store keys `key.<name>.short|long`.
Defaults: power = screen toggle (hold 3 s = reboot, fixed); vol ± = brightness (long: pages);
XCover = next page (long: USB mode toggle); top = previous page (long: status page). While the screen is off,
the first press only wakes. Built-in pages until M8: test/touch page and a status page (USB, IP, battery,
temperature, charging, uptime). Virtual keys via uinput (`ppctl keys inject <code> <ms>`) test the real evdev path.

## Issues found and fixed
- ttys hung up by a USB re-enumeration report `POLLIN|POLLHUP` and read EOF; paneld now reopens on HUP/EOF
  (before: the control channel was dead after a mode switch, and the loop spun).
- `udhcpd.conf` was never written (the sysfs helper doesn't create files); stale DHCP leases blocked the new MAC.
- Touch state was shared between touch devices (real panel + injector); the input core drops unchanged positions
  per device, so contacts picked up the other device's coordinates. Now per-device.
- Seen once, not reproduced (40/40 OK afterwards): the main loop spun in `ctl:touch` and the watchdog rebooted cleanly.
  Fine-grained breadcrumbs are left in place.
