# M11b verification: remote console over SSH (Samsung Galaxy XCover Pro)

Status: 🟨 2026-11-17. SSH into PhoneKit and through it onto a server's serial console works end to end over the
USB network; over Wi-Fi it's the same server on the phone's Wi-Fi address (not testable from the dev PC, which is on
a different network).

## How it works
- **dropbear 2026.94**, static (`scripts/build-wifi-tools.sh`), **password authentication not compiled in**: keys only.
  It runs only while at least one key is authorised; the ED25519 host key is generated once and kept in the settings
  store, so the phone's fingerprint survives reboots and updates.
- `ppctl ssh authorize "<ssh-ed25519 … comment>"` adds a key, `ppctl ssh revoke` removes all keys (dropbear stops),
  `ppctl ssh` shows status.
- `ssh root@<phone>` → PhoneKit's shell. `ssh root@<phone> pk-console` → the server's serial console (RESCUE's port):
  the phone's own terminal steps aside and shows "A remote SSH session is using the server console"; leave with
  `Enter ~ .` and the phone takes the console back.
- RESCUE now also carries the USB network, so the server gets `usb0` (10.42.0.1 by DHCP) and SSH to the phone works
  even while the server's own network is down.

| Check | Result |
|---|---|
| Authorised key → root shell | ✅ `uid=0(root)`, aarch64 |
| Password login | ✅ refused (`Permission denied (publickey)`) |
| Wrong key | ✅ refused |
| Host key stable across an update + reboot | ✅ strict host-key checking passed after `make update` |
| `pk-console` relays both ways | ✅ the stand-in server's bash answered `REMOTE_CONSOLE_OK_42` through SSH → phone → serial |
| Console handed back after the session | ✅ `rescue: console back from the remote session` |
| Over Wi-Fi from another machine | ✅ 2026-11-17: from the PC on the same home network, root shell with a throwaway key; password login refused. ~0.4 MB/s at a weak 2.4 GHz spot (Wi-Fi power save on or off made no difference) |

Test notes: `microcom` didn't relay on the gadget tty; a raw `stty` + two `cat`s does. With the USB network in the
RESCUE gadget the host's ttyACM numbering shifts: find the console port with `ppctl ports` (interface 04), not by
`ttyACMn`.
