# M10c verification: Bluetooth (Samsung Galaxy XCover Pro)

Status: 🟨 2026-11-17. `hci0` works under PhoneKit; the phone pairs with an Android phone as a Bluetooth keyboard +
mouse and types on it. Linux/Windows hosts and idle power are still to check.

## How it works
- Kernel: `CONFIG_BT`, `CONFIG_BT_BREDR`, `CONFIG_BT_LE`, `CONFIG_BT_HCIVHCI`, `CONFIG_BT_HIDP` in
  `kernel/phonepanel.cfg`. The vendor tree had `net/bluetooth/hci_sock.c` partly commented out (Samsung uses its own
  userspace stack), which doesn't compile with `CONFIG_BT=y`: `kernel-patches/0003` restores it from Android common
  `android-4.14-stable`.
- paneld (`bt.c`, `ppctl bt on|off|scan`): opens Samsung's raw H4 device `/dev/scsc_h4_0` (this starts the chip's
  Bluetooth service and loads `mx140_bt.hcf`) and bridges it to `/dev/vhci`, cutting the byte stream into HCI packets;
  the kernel registers `hci0` and runs its normal controller setup through the bridge. Packets the chip sends before
  `hci0` is up are dropped (`ENXIO`) instead of stopping the bridge.
- Off by default; `bt on` persists.

## The host's Bluetooth restarting (fixed)
The first version answered **every** SDP search with the HID record. Android also looks up the Device ID record
(UUID 0x1200, vendor/product) and got HID attributes in its place; once input reports arrived its stack restarted
(Bluetooth switched itself off on the host). Now searches return only records holding all UUIDs of the pattern,
attribute requests return only the attributes asked for, and there is a real Device ID record (0x1d6b:0x0246).

## Notes
- The host applies its own keyboard layout, as with any keyboard. PhoneKit sends US key codes and announces country
  code 33 (US) in its HID record; a host set to QWERTZ swaps Y/Z. Set the host's physical keyboard layout for
  "PhoneKit" to English (US) (Android: Settings → General management → Physical keyboard).
- `ppctl bt log` keeps the last 48 Bluetooth events (pairing, SDP, channels, control messages, first reports).
