# M12b verification: PHONEBOX mode with the stock phonebox agent (Samsung Galaxy XCover Pro)

Status: 🟨 2026-11-16. Works end to end with the **unmodified** phonebox agent 0.9.14 (Linux x64 release), default
config. `scripts/test-phonebox.py` all pass. Coverage of phonebox's 62 widget types is partial (table below).

## How it works
```
phonebox agent (PC) ──adb──► PhoneKit adbd (paneld/adbd.c)        "a phone with the phonebox app"
   │  devices, shell pm path / am start / input keyevent / settings put …  → emulated answers
   │  reverse tcp:8765 tcp:8765                                          → listener on the phone's 127.0.0.1:8765
   ▼
agent HTTP :8765 ◄──tunnel── PhoneKit native client (paneld/pbclient.c)
   GET /api/config  → pages/widgets → PPJ/1 layouts → panel.c draws them
   GET /api/stream  → "state" every second → value updates (only changed widgets redraw)
   POST /api/run/<id>, /api/media/<action>   ← taps on shortcut / media buttons
```
- The agent's own log on connect: `adb reverse set up, panel opened`, `phone connected`, `live stream opened (phone, USB/local)`.
- `am start` from the agent switches the phone to the PHONEBOX page; `input keyevent KEYCODE_SLEEP/WAKEUP`
  turns the screen off/on (the agent's "follow computer lock").
- The phone reports app version `99.0.0` so the agent never offers to install an APK update. An install request is
  answered "Success" and the APK is discarded.
- The USB ID in PHONEBOX mode is `18d1:4ee4` ("rndis,adb", as postmarketOS/PinePhone use), so the stock
  `51-android.rules` grant adb access without setup. No RSA auth yet: the cable already gives a root console.
- `adb shell` on PhoneKit is a real busybox shell (anything not emulated runs there): a nice dev bonus.

## Measured
| Check | Result |
|---|---|
| Host adb sees PhoneKit | ✅ `device … model:PhoneKit` on first plug-in |
| Agent detects the phone, sets up the tunnel, opens the panel | ✅ within ~4 s of adb coming up |
| Live state | ✅ 1 update/s, ~1.7 KB JSON each |
| Pages | ✅ 7 enabled default pages built (focus/world are disabled in the default config) |
| Rotation | ✅ landscape = phonebox's 12×6 grid 1:1; portrait transposes it |
| Tap → agent | ✅ `POST /api/media/playpause` (400 on this test PC: no `playerctl`, so no media backend) |
| Reverse tunnel throughput | ✅ 20 MB through `adb shell` / 8 MB `exec-out` intact |

## Widget coverage (phonebox type → PhoneKit)
| phonebox | PhoneKit | Notes |
|---|---|---|
| clock, worldclock, wordclock, analog | clock | digital only; worldclock shows local time |
| stat (cpu, gpu, ram, vram, net/down/up, ping, gputemp, cputemp) | value | unit and colour per metric |
| gauge | gauge | |
| chart (first metric) | graph | multi-metric charts show only the first |
| meters | 1–4 gauges | RAM, VRAM, disks |
| media | title + artist labels, PREV/PLAY/NEXT buttons | no artwork, no seek |
| shortcuts | buttons → `/api/run/<id>` | labels only (no emoji icons: the font is ASCII) |
| label, note, quote | label | |
| everything else (quotas, sessions, github, processes, forecast, weather, calendar, docker, obs, ha, …) | placeholder "TYPE (SOON)" | next |

## Notes
- Testing used an isolated agent (`HOME` pointed at a scratch folder) and stopped it before the phone rebooted
  into LineageOS: a running agent also configures any real Android phone it sees (stay-awake, screensaver settings).
- `scripts/phone.sh` now recognises PhoneKit's adbd (`getprop ro.phonekit`) and reboots it to the ROM instead of
  mistaking it for LineageOS.
