## 2026-11-15: control channel, hands-free loop, watchdog

- `make deploy`: dd over adb from LineageOS (userdebug, adb root), verified by sha256, `adb reboot recovery`.
  Serial port usable 25–30 s after the reboot command; paneld itself is ready 2.59 s after kernel start.
- USB gadget: configfs `acm.gs0` on UDC `13200000.dwc3`, enumerates as `1d6b:0104 phonepanel` with the phone's serial.
- **Freeze found and fixed.** The first control-channel build froze its main loop (screen and touch dead,
  needed Vol Down + Power). The cause was binary probe frames written into the port by some program on the
  host PC (`55 aa 55 aa 1e 00 01 00 …`, `… 55 04 33`), plus an early echo of paneld's own log lines.
  paneld answered every junk line, and each reply waited 5 s for a host that wasn't reading.
  Fixes: junk is ignored silently (logged in hex), replies are dropped when the host is deaf, and the
  watchdog only counts returning to `poll()` as progress. The original hang's log was lost: a forced reset boots
  recovery again and the next boots overwrote `last_kmsg`.
- **Watchdog verified on the phone.** `ppctl stall 40` → after 15.5 s it logged the phase, wchan, syscall and
  kernel stack, rebooted into LineageOS by itself, and `make logs` showed the dump
  (excerpt below). No buttons needed.
- Also verified on the phone: `run` timeout kill (30 s, rc 137) with paneld unaffected; `get /proc/kmsg`
  doesn't block; 400 KB `dmesg` transfers; charging works without Android (Fast, 33–190 mA).

## 2026-11-15: junk source found, 3-port layout, busybox shell

- The junk came from **a joystick daemon** on the dev PC (for an unrelated USB device), which polls
  `/dev/ttyACM0` at ~100 Hz with its own binary frames (`0x55` …). Evidence: the junk followed whichever phonepanel
  port was ACM0, and the second port never got any. Two readers on one tty also explain the lost reply bytes.
- New layout: ACM0 = read-only log port (decoy), ACM1 = control, ACM2 = shell. `ppctl` selects by
  USB interface number. Verified with the daemon running: zero junk on the control channel, three 380 KB
  `dmesg` transfers intact, `logtail` streams, shell answers.
- busybox 1.37.0 static (2.1 MB, `scripts/fetch.sh busybox && scripts/build-busybox.sh`, SHA HWACCEL off for arm64).
  The shell waits for one Enter before printing, so a host tty's open-time echo can't feed the prompt back.
- paneld now reaps all children (PID 1 duty) and respawns the shell.
- ppctl: O_NONBLOCK read retry fix.

## 2026-11-15: kernel from source, measured trimming

- Kernel builds from the LineageOS 24.0 fork with host clang/LLD 23 in ~2:45 (two host-toolchain patches:
  OpenSSL 4 ENGINE removal in extract-cert, CUDA line in `clang -v`). The untrimmed source kernel boots identically.
- `initcall_debug` measurement (fragment `kernel/debug-initcall.cfg`). Top costs:
  nvt_ts touch 637 ms, rt5665 codec 390 ms, speedy 109 ms, i2c adapters 86 ms, fimc-is 66 ms,
  rt5510 amp 44 ms, exynos audio 32 ms, NFC 16 ms.
- Results:
  | Change | Result |
  |---|---|
  | audio codecs + machine driver off | ✅ first frame 2.54 → **2.06 s** |
  | NFC/eSE off | ❌ hangs before the display comes up, no log (ESE_SECURE likely guards a TrustZone-owned SPI port). Reverted |
  | camera (fimc-is) off | ❌ link error: SM5713 flash-LED driver needs camera_class. Kept |
  | async probe for nt36672a touch | boots, but **no gain**: the kernel waits for async probes before /init. Dropped |
- **Safety lesson:** a kernel that hangs before paneld can't be recovered remotely. The Samsung bootloader keeps
  booting recovery after a forced reset, so it takes download mode (Vol Down+Power, then Vol Up+Vol Down)
  and heimdall. Keep `out/<device>/known-good.img` (prebuilt kernel + current paneld) and arm a watcher that
  flashes it as soon as download mode appears. This cost the user three download-mode trips.
