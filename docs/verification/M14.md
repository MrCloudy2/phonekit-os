# M14 verification: updates (Samsung Galaxy XCover Pro)

Status: 🟨 2026-11-17. Self-update from PhoneKit works (`make update`). Safe mode and the agent-driven update
button are pending.

## `make update` (scripts/pk-update.sh)
1. Upload the partition-sized image over the USB control channel to `/tmp` (RAM): **~35 MB/s** (20 MB in 0.57 s).
2. On the phone: find the partition by name, check its size, check the upload's sha256.
3. Write everything except the settings store (`[end-2 MiB, end-1 MiB)`), `fsync`, drop caches, read back and
   compare the sha256 of the written regions.
4. Only then reboot into it.

| Check | Result |
|---|---|
| Build → running new image | ✅ **13 s** (was ~2.5 min through the ROM with `make deploy`) |
| Upload verified, write read back | ✅ `written and verified /dev/sda13 (settings store kept)` |
| Settings survive | ✅ USB mode, rotation, standby, Wi-Fi network (re-joined by itself after the reboot) |
| A stalled upload doesn't wedge the control channel | ✅ a `put` with no data for 10 s is abandoned (found when a client died mid-upload) |

## Failure model (no A/B slots on this phone)
- Anything failing before step 3 changes nothing.
- A write interrupted half-way leaves a broken recovery partition: the ROM on `boot` still starts, and
  `make deploy` (or download mode) restores PhoneKit.
- A new image that hangs: paneld's watchdog reboots into the ROM. A kernel that panics early loops into
  recovery: download mode + the known-good image (docs/recovery.md).
