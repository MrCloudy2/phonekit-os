# M6 verification: Mode A, USB monitor + touchscreen (Samsung Galaxy XCover Pro)

Status: ✅ confirmed 2026-11-15 on a Linux PC (kernel 7.3, KDE Plasma Wayland, 3 monitors).

| Confirm item | Result |
|---|---|
| Linux PC sees a new monitor + touchscreen with no extra install | ✅ mainline `gud` binds (`[drm] Initialized gud 1.0.0`), KDE adds output `USB-1`; `hid-multitouch` touchscreen. Raspberry Pi not tested (none at hand) |
| 60 fps at native resolution, compressed RGB565 over USB 2.0 | 🟨 full 1080×2340 frames changing every frame: **53 fps** (testsrc2), **30 fps** for content that compresses badly (USB-bound, ~17 ms/frame). Desktop use sends only damaged regions |
| Touch maps 1:1 to the right monitor on a multi-monitor host | ✅ Wayland/KDE, after mapping the device to `USB-1` once (KWin saves it per device). User-verified with a real finger. X11 not tested |
| Idle host desktop → phone stays idle (no flushes) | ✅ 0 frames in 10 s |

## Implementation (paneld/gud.c)
- GUD device over FunctionFS (protocol: `include/drm/gud.h` from the host kernel headers). Mode A uses the GUD
  USB ID **1d50:614d**, which the host driver binds to; host tools now find the phone by manufacturer + interface.
- Formats: **RGB565** on the wire (default; the host converts) or XRGB8888 (`store set gud_format xrgb8888`).
  **LZ4** (`gud_lz4`, default on): flat UI content compresses to ~0.5 %. Decoder fuzzed against liblz4 under ASan.
- Connector: one PANEL, one mode (1080×2340@60), backlight property (PC brightness slider → phone backlight),
  DPMS → M4 power manager.
- Threads (all on the fast A73 cluster): ep0 control; bulk receive; render (LZ4 + convert); async pan.
  Receive of frame N+1 overlaps render of frame N.

## Measured per full frame (testsrc2)
| Stage | Time |
|---|---|
| USB receive (LZ4-compressed) | 8 ms |
| LZ4 decompress | 3 ms |
| RGB565 → panel conversion (`-O3`) | 5 ms (13 ms at `-Os`) |
| pan (async, off the critical path) | — |
Parallel conversion was **slower** (2–3 workers: 16–20 ms): the threads contend for framebuffer memory bandwidth. Kept at 1.

## Host-side settings that matter
- `gud` module parameter **`async_flush=1`** (default off): pipelines the host's conversion/compression with the
  USB transfer. 26.6 → 33.8 fps alone, 53 fps together with the phone-side pipeline.
  Runtime: `echo Y | sudo tee /sys/module/gud/parameters/async_flush`; permanent: `/etc/modprobe.d/gud.conf`
  with `options gud async_flush=1`.
- KDE first picked **scale 0.4** for the 420-dpi panel (everything tiny). Set 2.5:
  `kscreen-doctor output.USB-1.scale.2.5`.
- KWin left the touchscreen unmapped (→ primary monitor). Map once:
  `busctl --user set-property org.kde.KWin /org/kde/KWin/InputDevice/eventN org.kde.KWin.InputDevice outputName s USB-1`
  (or System Settings → Touchscreen).

## Bugs found on the way
- **Panel is BGR** although fbdev reports RGB: red/blue were swapped everywhere (incl. M0). Device quirk
  `FB_SWAP_RB`, verified by eye with `ppctl colortest`. Screenshots now use the true order.
- In GUD mode paneld skipped drawing touch strokes, and HID reports were only sent for frames that drew, so
  real touches never reached the host. Touch frames are now forwarded regardless of drawing.
